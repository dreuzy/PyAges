(external-lpm-quickstart)=
# External LPM plugin quickstart

Use this guide when your model must live outside the PyAges repository. You
will generate a standalone package, install it locally, verify it, and build the
model through the ordinary PyAges API.

The generated code runs immediately, but it contains example mathematics. A
successful system check proves that the plugin is integrated correctly; it does
not prove that the distribution is scientifically appropriate.

## 1. Choose a starting point

Choose `scipy` when a suitable distribution already exists in `scipy.stats`:

```console
pyages new lpm my_model --layout plugin --base scipy
```

Choose `root` for a custom, discrete, mixed, or otherwise special law:

```console
pyages new lpm my_model --layout plugin --base root
```

The model name must use `snake_case`: lowercase letters, digits, and
underscores, starting with a letter.

## 2. Inspect the generated project

The command creates:

```text
pyages-lpm-my-model/
├── pyproject.toml
├── README.md
├── src/
│   └── pyages_lpm_my_model/
│       ├── __init__.py
│       ├── model.py
│       └── data_lpm/
│           └── my_model/
│               └── params.yaml
└── tests/
    └── test_model.py
```

Read and edit the files in this order:

1. `model.py`: replace the starter distribution with your mathematics.
2. `params.yaml`: make names, units, domains, ranges, initial values, steps,
   and priors agree with the model.
3. `test_model.py`: add analytical values or trusted reference results.
4. `pyproject.toml`: review package metadata, dependencies, and versions.

The generated Python files contain explanatory module, class, and method
docstrings. Search for `Generated by` and replace the copyright placeholder
before publishing the package.

## 3. Keep code and parameters synchronized

The constructor and YAML file describe the same public parameters. If the
constructor contains:

```python
values = {"mu": mu, "shape": shape}
units = {"mu": "year", "shape": "-"}
```

then `params.yaml` must contain exactly the `mu` and `shape` parameter entries
with compatible units.

### Read one parameter entry

A typical strictly positive parameter contains:

```yaml
- name: mu
  unit: year
  domain: {min: 0.0, min_inclusive: false, max: null}
  calibration_range: [0.1, 200.0]
  init: 10.0
  step: 1.0
  prior: {type: uniform, min: 0.1, max: 200.0, unit: year}
```

Read the nested limits from broadest to narrowest:

```text
mathematical domain:        mu > 0
calibration range:          0.1 <= mu <= 200
initial value:              mu = 10
uniform-prior support:      0.1 <= mu <= 200
```

`min_inclusive` controls whether the exact minimum belongs to the mathematical
domain:

- `min_inclusive: false` means `value > min`; the boundary is excluded;
- `min_inclusive: true` means `value >= min`; the boundary is included.

`max_inclusive` works in the same way for a finite maximum. Both flags default
to `true` when omitted. A `null` minimum or maximum means that side of the
mathematical domain is unbounded.

Do not confuse `domain` and `calibration_range`. The domain states where the
formula is mathematically valid. The calibration range is the finite interval
chosen for one practical search and must lie inside the domain.

The complete field-by-field syntax is in the
{ref}`LPM parameter-file reference <lpm-parameter-file-reference>`. The
executable validation rules are implemented in
`pyages/data_io/_lpm_parameter_schema.py`; focused examples of accepted and
rejected documents are in `tests/data_io/test_lpm_params.py`.

For a continuous model, implement:

```python
def cdf_and_partial_first_moment(self, t):
    ...
```

It returns both:

- `F(t)`, the cumulative probability;
- `E[T 1(T <= t)]`, the unnormalized first moment below `t`.

This second quantity is required by the continuous convolution engine. It is a
scientific requirement, not plugin bookkeeping.

## 4. Install the plugin locally

Move into the generated directory and install it in editable mode:

```console
cd pyages-lpm-my-model
python -m pip install -e .
```

Editable installation records the plugin metadata while leaving the source
files editable. You do not need to publish anything to PyPI while developing.

## 5. Check discovery and integration

```console
pyages list lpms
pyages check lpm my_model
pytest
```

`pyages list lpms` confirms that the installed metadata is visible.

`pyages check lpm my_model` checks packaging, the parameter schema,
vectorization, distribution invariants, moments, and the declared convolution
strategy. Fix every failure before attempting calibration.

`pytest` runs the plugin's own scientific tests. Extend those tests beyond the
generated smoke test.

These two commands answer different questions:

| Command | Question answered |
| --- | --- |
| `pyages check lpm my_model` | Can PyAges load and safely exercise this model through the common LPM contract? |
| `pytest` | Do this model's own formulas agree with analytical or trusted reference results? |

The complete list of common checker probes is in
{ref}`external-lpm-integration-checking`. For the repository test suite more
generally, {doc}`../dev/testing` explains the test families and commands, while
the generated {doc}`../dev/test-inventory` lists every test module and its
collected-case count. `python run_tests.py collect` prints the exact individual
pytest case identifiers.

## 6. Use the model normally

No explicit plugin import is required:

```python
from pyages.lpm import build_lpm

model = build_lpm("my_model")
print(model.mean())
```

To override the packaged parameter schema for one study:

```python
model = build_lpm("my_model", directory_lpm="study_lpm_parameters")
```

The override directory must contain `my_model/params.yaml`.

## 7. Compare the two maintained examples

The repository includes two complete, independently installable plugins. They
have the same package structure and PyAges contract, but different scientific
implementation strategies.

| Example | Base | What the model implements |
| --- | --- | --- |
| `examples/templates/external_lpm_plugin_scipy` | `LpmScipy` | Parameter conversion and the gamma partial moment; SciPy supplies PDF, CDF, quantile, mean, and standard deviation |
| `examples/templates/external_lpm_plugin` | `LpmBase` | Every probability function and moment directly with NumPy |

Try the SciPy-backed gamma example:

```console
cd examples/templates/external_lpm_plugin_scipy
python -m pip install -e .
pyages check lpm gamma_mean
pytest
```

Try the independent bounded-power example:

```console
cd examples/templates/external_lpm_plugin
python -m pip install -e .
pyages check lpm bounded_power
pytest
```

Read each README and then compare the two short `model.py` files. The PyAges
test suite also copies both examples to temporary directories, installs them,
runs their own tests, and checks them from new processes. This guards the
actual packaging and entry-point boundary.

## Common problems

### The model is not listed

Confirm that the package was installed with the same Python environment used by
the `pyages` command:

```console
python -m pip show pyages-lpm-my-model
python -m pip show pyages
```

Then inspect `[project.entry-points."pyages.lpms"]` in `pyproject.toml`.

### The name is reported as a conflict

Two providers advertise the same model name. PyAges refuses to choose based on
installation order. Uninstall one provider or rename one model.

### `params.yaml` is missing

Check both the package-data rule in `pyproject.toml` and this layout:

```text
src/pyages_lpm_my_model/data_lpm/my_model/params.yaml
```

### The check passes but the science is wrong

The integration checker cannot establish scientific validity. Add tests for
normalization, boundaries, exact moments, quantiles, partial moments, limiting
cases, and trusted reference values relevant to your distribution.
